## Успадкування узагальнених класів, Comparable та Comparator

### 🎯 Що ви навчитеся робити

Робити з власного узагальненого класу конкретний: `GenericRepository<T>` із ЛР4 стає батьком для репозиторіїв вашого домену. Задавати об'єктам природний порядок і писати порівняння, які не ламаються на дробових числах. Бачити, що порядок — це не лише про вивід на екран: від нього залежить, чи знайдеться об'єкт у колекції.

### 📋 Що зробити

**1. Доменні репозиторії.** Оберіть дві сутності свого домену й створіть для кожної репозиторій, успадкований від `GenericRepository<T>`:

```java
public class RoomRepository extends GenericRepository<Room> {
    public RoomRepository() {
        super("rooms", Room::number);
    }
    ...
}
```

Екстрактор передаєте посиланням на метод, не лямбдою. `GenericRepository` при цьому не переписується під конкретні сутності: усе доменне живе у спадкоємцях.

**2. Природний порядок: `Comparable<T>`.** Для обох сутностей із пункту 1 реалізуйте `Comparable<T>` за основним полем.

Порівнюєте через `Integer.compare`, `Double.compare`, `String.compareTo` або `Comparator.comparing`. Віднімання — `a.year() - b.year()`, `(int)(a.price() - b.price())` — заборонене: перше переповнюється, друге на дробових цінах дає 0 там, де різниця є.

`compareTo` має бути узгоджений з `equals`: якщо `compareTo` повертає 0, то `equals` повертає `true`. Якщо основне поле не унікальне, доберіть друге через `thenComparing`.

**3. Сортування в `GenericRepository<T>`.** Додайте два методи:

```java
public List<T> findAllSorted(Comparator<T> comparator)
public List<T> findAllSortedByIdentity(SortOrder order)
```

`SortOrder` — enum із двома константами (`ASC`, `DESC`) у тому самому пакеті, що й репозиторій. Як саме він впливає на порядок — ваше рішення, на захисті поясните.

Перший метод приймає порядок аргументом — так само, як у ЛР4 приймав `IdentityExtractor`. Другий сортує за ключами, які репозиторій і так тримає.

Жодних рядків на кшталт `"asc"` у сигнатурах.

**4. Доменні методи сортування.** У кожному репозиторії з пункту 1 — щонайменше три методи сортування за різними критеріями домену, усередині яких викликається успадкований `findAllSorted(...)`.

Компаратори описуєте лямбдами й посиланнями на методи. Щонайменше один має бути багаторівневим: `thenComparing` і `reversed`, а якщо поле може бути порожнім — `nullsLast`.

**5. Колекція з компаратором.** Покажіть `TreeSet` або `TreeMap`, створений із власним компаратором.

Покладіть туди два різні об'єкти, які цей компаратор вважає рівними, і подивіться, скільки елементів у колекції. Поясніть результат — у `README.md` гілки `lab5`, трьома-чотирма реченнями.

**6. Логування через SLF4J** — ті самі три рівні, що й раніше: за якими критеріями сортували й скільки елементів повернули.

**7. Тести на JUnit 5, щонайменше шість:**

- природний порядок: `Collections.sort` на списку дає очікувану послідовність;
- багаторівневий компаратор: елементи з однаковим першим ключем впорядковані за другим;
- `findAllSortedByIdentity` у `ASC` і `DESC` дають взаємно обернені списки;
- стабільність: два елементи, рівні з точки зору компаратора, лишаються в порядку додавання;
- два об'єкти з різницею в ціні менш ніж одиниця сортуються правильно;
- `TreeSet` із компаратором, що не узгоджений з `equals`, поводиться так, як ви описали в `README`.

**8. Оновіть `Main`.** Показати треба:

1. наповнення двох доменних репозиторіїв;
2. сортування за природним порядком;
3. сортування за трьома доменними критеріями, один із них багаторівневий;
4. `findAllSortedByIdentity` в обидва боки;
5. поведінку `TreeSet` або `TreeMap` з компаратором;
6. логування.

### ✍️ Оформлення

Коментарі, javadoc, `@DisplayName` і тексти виключень — англійською. Українською — тільки те, що бачить користувач: рядки виводу в `Main`.

Raw types заборонені. Поля `GenericRepository` лишаються приватними — якщо спадкоємцю чогось не вистачає, додаєте публічний метод, а не послаблюєте доступ.
