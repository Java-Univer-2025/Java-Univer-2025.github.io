# Лабораторна робота №5
## Comparable, Comparator та Stream API

**Максимальна оцінка — 19 балів.**

### 🎯 Що ви навчитеся робити

Робити з власного узагальненого класу конкретний: `GenericRepository<T>` із ЛР4 стає батьком для репозиторіїв вашого домену. Задавати об'єктам природний порядок і писати порівняння, які не ламаються на дробових числах. Описувати пошук як послідовність перетворень, а не як цикл із прапорцями. Повертати з методу те, що чесно описує результат: `Optional`, коли об'єкта може не бути, і згрупований `Map`, коли результат — не плаский список.

### 📋 Що зробити

#### Частина 1. Репозиторії та порядок

**1. Доменні репозиторії.** Оберіть дві сутності свого домену й створіть для кожної репозиторій, успадкований від `GenericRepository<T>`:

```java
public class RoomRepository extends GenericRepository<Room> {
    public RoomRepository() {
        super("rooms", Room::number);
    }
    ...
}
```

Екстрактор передаєте посиланням на метод, не лямбдою. `GenericRepository` при цьому не переписується під конкретні сутності: усе доменне живе у спадкоємцях.

**2. Природний порядок: `Comparable<T>`.** Для обох сутностей із пункту 1 реалізуйте `Comparable<T>` за основним полем.

Порівнюєте через `Integer.compare`, `Double.compare`, `String.compareTo` або `Comparator.comparing`. Віднімання — `a.year() - b.year()`, `(int)(a.price() - b.price())` — заборонене: перше переповнюється, друге на дробових цінах дає 0 там, де різниця є.

`compareTo` має бути узгоджений з `equals`: якщо `compareTo` повертає 0, то `equals` повертає `true`. Якщо основне поле не унікальне, доберіть друге через `thenComparing`.

**3. Сортування в `GenericRepository<T>`.** Додайте два методи:

```java
public List<T> findAllSorted(Comparator<T> comparator)
public List<T> findAllSortedByIdentity(SortOrder order)
```

Усередині обох — стрім із `sorted(...)`.

`SortOrder` — enum із двома константами (`ASC`, `DESC`) у тому самому пакеті, що й репозиторій. Як саме він впливає на порядок — ваше рішення, на захисті поясните.

Перший метод приймає порядок аргументом — так само, як у ЛР4 приймав `IdentityExtractor`. Другий сортує за ключами, які репозиторій і так тримає.

Жодних рядків на кшталт `"asc"` у сигнатурах.

**4. Доменні методи сортування.** У кожному репозиторії з пункту 1 — щонайменше два методи сортування за різними критеріями домену, усередині яких викликається успадкований `findAllSorted(...)`.

Компаратори описуєте лямбдами й посиланнями на методи. Щонайменше один має бути багаторівневим: `thenComparing` і `reversed`, а якщо поле може бути порожнім — `nullsLast`.

**5. Колекція з компаратором.** Покажіть `TreeSet` або `TreeMap`, створений із власним компаратором.

Покладіть туди два різні об'єкти, які цей компаратор вважає рівними, і подивіться, скільки елементів у колекції. Поясніть результат — у `README.md` гілки `lab5`, трьома-чотирма реченнями.

#### Частина 2. Пошук через Stream API

**6. Методи пошуку в доменних репозиторіях.** У кожному репозиторії з пункту 1 — по одному методу на кожен вид пошуку:

- за точним або частковим збігом текстового поля;
- за діапазоном числового поля або дат;
- за двома умовами одночасно.

Усередині — стрім над вмістом репозиторію. Задійте `filter`, `map`, `sorted`, `distinct`, `limit` — кожен там, де він справді потрібен.

Якщо у вашому домені є сутність із вкладеною колекцією, покажіть на ній `flatMap`. Якщо такої сутності немає, цей пункт вас не стосується.

**7. Пошук одного об'єкта.** Метод, який шукає один об'єкт, повертає `Optional<T>` і отримує його через `findFirst`.

**8. Групування та агрегація.** У доменних репозиторіях — ще три методи, кожен із власним типом результату:

- розподіл об'єктів за полем: `Collectors.groupingBy`, результат `Map<Ключ, List<T>>`;
- підрахунок по групах: `groupingBy` із другим колектором — `counting`, `averagingDouble` або `summingInt`;
- зведення всієї колекції до одного числа — через `reduce` або через готовий метод (`sum`, `max`, `summaryStatistics`).

Методи можна розкласти між репозиторіями — усі три в одному не обов'язкові.

**9. Стрім назовні.** Додайте в `GenericRepository<T>` метод, що повертає `Stream<T>`. Чим він відрізняється від `findAll()`, який віддає захисну копію списку, — питання на захист.

**10. Одноразовість стріму.** Покажіть у `Main`, що відбувається при спробі використати вже спожитий стрім. Виключення перехопіть і залогуйте, програма не падає.

#### Частина 3. Логування, тести, `Main`

**11. Логування через SLF4J** — ті самі три рівні, що й раніше. На кожне сортування: за яким критерієм сортували й скільки елементів повернули. На кожен пошук: за яким критерієм шукали і скільки знайшли. Порожній результат пошуку — окремим рівнем.

**12. Тести на JUnit 5, щонайменше десять:**

- природний порядок: `Collections.sort` на списку дає очікувану послідовність;
- багаторівневий компаратор: елементи з однаковим першим ключем впорядковані за другим;
- `findAllSortedByIdentity` у `ASC` і `DESC` дають взаємно обернені списки;
- два об'єкти з різницею в ціні менш ніж одиниця сортуються правильно;
- `TreeSet` із компаратором, що не узгоджений з `equals`, поводиться так, як ви описали в `README`;
- кожен із методів пошуку знаходить те, що має: пошук за діапазоном не включає значення за межами, пошук за двома умовами не повертає об'єкт, що задовольняє лише одну;
- метод, який шукає один об'єкт, повертає `Optional.empty()`, коли збігів немає;
- `groupingBy` дає очікувану кількість груп і очікуваний розмір однієї з них;
- агрегація на порожній колекції не падає й повертає осмислене значення;
- повторне використання стріму кидає виключення.

**13. Оновіть `Main`.** Показати треба:

1. наповнення двох доменних репозиторіїв;
2. сортування за природним порядком і за доменними критеріями, один із них багаторівневий;
3. `findAllSortedByIdentity` в обидва боки;
4. поведінку `TreeSet` або `TreeMap` з компаратором;
5. пошук за кожним із реалізованих критеріїв;
6. результат, якого немає: розпаковуєте `Optional` через `orElse`, `orElseGet`, `orElseThrow`, `ifPresent` або `map`. Зв'язка `isPresent()` + `get()` не приймається — це той самий `if` на `null`, лише довший;
7. групування й агрегацію з виводом;
8. спробу пройти стрім двічі;
9. логування.

### ✍️ Оформлення

Коментарі, javadoc, `@DisplayName` і тексти виключень — англійською. Українською — тільки те, що бачить користувач: рядки виводу в `Main`.

Raw types заборонені. Поля `GenericRepository` лишаються приватними — якщо спадкоємцю чогось не вистачає, додаєте публічний метод, а не послаблюєте доступ.

Цикли `for` у методах сортування й пошуку — теж заборонені: якщо стрім виходить незрозумілим, розбийте його на два методи, а не повертайтеся до циклу.
