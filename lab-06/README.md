# Лабораторна робота №6
## Stream API

**Максимальна оцінка — 10 балів.**

### 🎯 Що ви навчитеся робити

Описувати пошук як послідовність перетворень, а не як цикл із прапорцями. Повертати з методу те, що чесно описує результат: `Optional`, коли об'єкта може не бути, і згрупований `Map`, коли результат — не плаский список. Бачити, де стрім закінчується і чому його не можна пройти двічі.

---

### 📦 Де працюєте

Репозиторій той самий — домен і варіант теж.

Після того як PR ЛР5 змерджено:

```
git checkout main
git pull
git checkout -b lab6
```

Здаєте через pull request `lab6` → `main`, захист — по діффу у вашому PR.

Працюєте в доменних репозиторіях із ЛР5. Цикли `for` у методах пошуку не використовуєте — усе через Stream API.

### 📋 Що зробити

**1. Методи пошуку в доменних репозиторіях.** У кожному репозиторії з ЛР5 — по одному методу на кожен вид пошуку:

- за точним або частковим збігом текстового поля;
- за діапазоном числового поля або дат;
- за двома умовами одночасно.

Усередині — стрім над вмістом репозиторію. Задійте `filter`, `map`, `sorted`, `distinct`, `limit` — кожен там, де він справді потрібен.

Якщо у вашому домені є сутність із вкладеною колекцією, покажіть на ній `flatMap`. Якщо такої сутності немає, цей пункт вас не стосується.

**2. Пошук одного об'єкта.** Метод, який шукає один об'єкт, повертає `Optional<T>` і отримує його через `findFirst`.

**3. Групування та агрегація.** У доменних репозиторіях — ще три методи, кожен із власним типом результату:

- розподіл об'єктів за полем: `Collectors.groupingBy`, результат `Map<Ключ, List<T>>`;
- підрахунок по групах: `groupingBy` із другим колектором — `counting`, `averagingDouble` або `summingInt`;
- зведення всієї колекції до одного числа — через `reduce` або через готовий метод (`sum`, `max`, `summaryStatistics`).

Методи можна розкласти між репозиторіями — усі три в одному не обов'язкові.

**4. Стрім назовні.** Додайте в `GenericRepository<T>` метод, що повертає `Stream<T>`. Чим він відрізняється від `findAll()`, який віддає захисну копію списку, — питання на захист.

**5. Одноразовість стріму.** Покажіть у `Main`, що відбувається при спробі використати вже спожитий стрім. Виключення перехопіть і залогуйте, програма не падає.

**6. Логування через SLF4J** — на кожен виклик методу пошуку: за яким критерієм шукали і скільки елементів знайшли. Порожній результат — окремим рівнем.

**7. Тести на JUnit 5, щонайменше вісім:**

- кожен із методів пошуку знаходить те, що має;
- пошук за діапазоном не включає значення за межами;
- пошук за двома умовами не повертає об'єкт, що задовольняє лише одну;
- метод, який шукає один об'єкт, повертає `Optional.empty()`, коли збігів немає;
- `groupingBy` дає очікувану кількість груп і очікуваний розмір однієї з них;
- агрегація на порожній колекції не падає й повертає осмислене значення;
- повторне використання стріму кидає виключення.

**8. Оновіть `Main`.** Показати треба:

1. наповнення доменних репозиторіїв;
2. пошук за кожним із реалізованих критеріїв;
3. результат, якого немає: розпаковуєте `Optional` через `orElse`, `orElseGet`, `orElseThrow`, `ifPresent` або `map`. Зв'язка `isPresent()` + `get()` не приймається — це той самий `if` на `null`, лише довший;
4. групування й агрегацію з виводом;
5. спробу пройти стрім двічі;
6. логування.

### ✍️ Оформлення

Коментарі, javadoc, `@DisplayName` і тексти виключень — англійською. Українською — тільки те, що бачить користувач: рядки виводу в `Main`.

Raw types заборонені. Цикли `for` у методах пошуку — теж: якщо стрім виходить незрозумілим, розбийте його на два методи, а не повертайтеся до циклу.
